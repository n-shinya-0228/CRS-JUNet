Measured Runtime Contributors
-----------------------------
1. The training phase, including its data pipeline, accounts for 91.514%
   of the observed epoch. Validation accounts for the remaining 8.486%.
   Batch size 2 gives 9565 optimizer steps per epoch and 956500 steps over
   100 epochs. This step count directly contributes to the total duration.

2. The dataset rebuilds both projections from raw point clouds in every
   __getitem__ call: dataset.py:88 -> projection.py:133. A CPU-only cProfile
   probe of 12 actual training scans, with the original augmentation and
   Copy-Paste enabled, measured these cumulative times:

   Dataset __getitem__ total:       0.641897 s (100% of dataset time).
   build_dual_projection:           0.569485 s (88.72% of dataset time).
   _make_bev_projection:            0.355434 s (55.37% of dataset time).
   _make_spherical_projection:      0.185328 s (28.87% of dataset time).
   apply_copy_paste:                0.012169 s (1.90% of dataset time).

   Projection construction is the main measured dataset-side cost;
   Copy-Paste is not the main dataset-side cost in this small sample.
   The code performs these projections again each epoch rather than
   reading the precomputed BEV/PointNet tensors used by earlier runs.

   These are nested cumulative times: do not add parent and child rows.
   Percentages describe dataset preparation only, NOT full-training time.
   The separate probe ran on CPU concurrently with training, includes
   profiler overhead, and does not prove DataLoader is the critical path.

3. Live GPU utilization stayed at 90-93% in the sampling window. The
   device was active most of the time rather than mostly idle waiting
   for data. No individual GPU operator is identified as the bottleneck
   from these utilization counters.
